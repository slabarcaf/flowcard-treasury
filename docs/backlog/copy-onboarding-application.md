# Copy an onboarding application into a new draft

Allow an operator to create a new DRAFT application from a closed onboarding
application. This reduces repeated data entry when a submission is definitively
refused and the operator must review and correct the application before trying
again. The original application and its submissions remain immutable history.

Define which details to reuse, whether company details come from the current
Company or the previous application, and whether application-owned documents
must be uploaded again or explicitly copied. Do not copy submission identities,
decisions, information-request state, or pending platform operations. Preserve
the one-open-application rule and the existing Platform Account relationship.

This is deferred UX work from the company-onboarding domain brainstorm. An
uncertain platform outcome must be reconciled before copying can enable another
submission. Copying must not automatically submit or create a Platform Account.
